# Database & Data Storage

## What It Does

The app stores all scan results, analysis data, and settings in a local SQLite database. This means:

- **Fast startup** - No re-scanning needed after restart
- **Persistent history** - Action logs survive app updates
- **Portable data** - Database can be backed up or moved
- **Offline operation** - No internet required

## Database Location

### Default Location

Windows: `C:\Users\[Username]\AppData\Local\NASDedup\nasdedup.db`

### Changing the Location

**Settings > Database > Database Location:**

```
DATABASE LOCATION

Current: C:\Users\clint\AppData\Local\NASDedup\nasdedup.db
Size: 234.5 MB

[Change Location] [Open Folder]

Moving the database will:
- Copy all data to the new location
- Update app to use the new location
- Optionally delete the old database
```

**Good locations:**
- Local SSD for best performance
- Backed-up folder for safety
- NOT on network drive (slow)

## What's Stored

### Files Table

Every file discovered during scanning:

| Data | Purpose |
|------|---------|
| Path | Full path to the file |
| Drive ID | Which drive it's on |
| Size | File size in bytes |
| Created/Modified | File timestamps |
| File type | Extension, MIME type |
| Content hash | SHA-256 for duplicate detection |
| Quick hash | xxHash for fast comparison |
| Perceptual hash | For image similarity |

**Size estimate:** ~500 bytes per file. 100,000 files ≈ 50 MB.

### Metadata Table

EXIF and extracted metadata:

| Data | Purpose |
|------|---------|
| EXIF date | Original capture timestamp |
| GPS coordinates | Location where photo was taken |
| Camera info | Make, model, settings |
| Image dimensions | Width, height |
| Video duration | Length of video files |

**Size estimate:** ~200 bytes per file with metadata.

### Duplicate Groups

Information about duplicate clusters:

| Data | Purpose |
|------|---------|
| Group ID | Unique identifier |
| Match type | Exact or near-duplicate |
| Similarity | Percentage match |
| File list | Which files are in the group |
| Resolution status | Pending, resolved, ignored |

### Face Data

Face detection and recognition data:

| Data | Purpose |
|------|---------|
| Face ID | Unique identifier |
| Bounding box | Location in image |
| Embedding | 512-float face fingerprint |
| Person ID | Who this face belongs to |
| Confidence | Recognition certainty |
| Age estimate | Apparent age |

**Size estimate:** ~2 KB per detected face. 50,000 faces ≈ 100 MB.

### People Table

Named individuals:

| Data | Purpose |
|------|---------|
| Person ID | Unique identifier |
| Name | User-assigned name |
| Reference faces | Sample face embeddings |
| Photo count | How many photos they appear in |

### Scene Analysis

AI-generated content tags:

| Data | Purpose |
|------|---------|
| File ID | Which image |
| Scene categories | Beach, mountain, party, etc. |
| Objects detected | Dog, car, cake, etc. |
| Quality score | Image quality rating |
| CLIP embedding | For semantic search |

**Size estimate:** ~500 bytes per analyzed image (plus ~2KB for CLIP embedding).

### AI Summaries

Rich natural language descriptions generated by AI:

| Data | Purpose |
|------|---------|
| File ID | Which file |
| Summary | Natural language description |
| Summary model | Which AI model was used |
| People mentioned | JSON list of people in the content |
| Activities | JSON list of activities detected |
| Mood/atmosphere | Emotional tone of the content |
| Time of day | When photo was taken (morning, sunset, etc.) |
| Season/weather | Environmental context |
| Document type | For docs: invoice, receipt, letter, etc. |
| Document summary | Key info extracted from documents |
| Key entities | JSON of names, dates, amounts, etc. |
| User edited | Whether user modified the summary |

**Size estimate:** ~1-2 KB per file with summary.

### Tags

Searchable tags for categorizing files:

| Data | Purpose |
|------|---------|
| Tag ID | Unique identifier |
| Name | Tag name (e.g., "beach", "birthday") |
| Category | person, place, activity, object, event, custom |
| Is system | Whether it's a built-in tag |

### File Tags

Association between files and tags:

| Data | Purpose |
|------|---------|
| File ID | Which file |
| Tag ID | Which tag |
| Confidence | AI confidence (0.0-1.0) or 1.0 for user tags |
| Source | ai, user, or exif |

**Size estimate:** ~50 bytes per file-tag association.

### OCR Results

Text extracted from images and documents:

| Data | Purpose |
|------|---------|
| File ID | Which file |
| Extracted text | Full text content |
| Confidence | OCR confidence score |
| Language | Detected language |

**Size estimate:** Variable based on text content.

### Action Log

History of all file operations:

| Data | Purpose |
|------|---------|
| Timestamp | When action occurred |
| Action type | Delete, move, quarantine |
| Source/destination | File paths |
| File hash | For verification |
| Status | Success, failed, undone |

**Size estimate:** ~200 bytes per action.

### Migrating to New Computer

To move everything to a new computer:

1. **Old computer:** Export full SQLite database
2. **New computer:** Install app
3. **New computer:** Import the database
4. **New computer:** Re-scan to verify files still exist at same paths

If paths changed (different drive letters):

**Settings > Database > Path Migration:**

```
PATH MIGRATION

Update paths in database to reflect new locations.

Old path prefix: D:\Photos
New path prefix: E:\Photos

Files to update: 45,234

[Preview Changes] [Apply]
```

## Data Privacy

### What's NOT Stored

The database does NOT contain:
- Actual file contents
- Full-resolution images
- Passwords or credentials
- Any data sent to cloud services

### Face Embedding Privacy

Face embeddings are mathematical representations:
- Cannot be reversed to generate a face image
- Only useful for matching within this app
- Deleted when you delete a person

### Encryption (Optional)

Enable database encryption:

**Settings > Database > Security:**

```
DATABASE ENCRYPTION

[ ] Encrypt database with password

When enabled:
- Database is encrypted at rest
- Password required on app startup
- Protects face and file data

[Enable Encryption]

Warning: If you forget the password, data cannot be recovered.
```

## Troubleshooting

### "Database is locked"

The database can only be opened by one process at a time.

**Causes:**
- Another instance of the app is running
- App crashed and left lock file

**Solutions:**
1. Close any other instances
2. Check Task Manager for running processes
3. Delete the `.db-lock` file if app isn't running

### "Database is corrupted"

Rare, but can happen after crashes or disk errors.

**Solutions:**
1. Try **Settings > Database > Repair**
2. Restore from automatic backup
3. Worst case: Delete database and re-scan

### Database too large

If the database grows very large:

1. **Clear old action logs** - Usually the biggest growth area
2. **Remove deleted file entries** - Files that no longer exist
3. **Optimize database** - Reclaim fragmented space
4. **Consider SSD** - Large databases work better on SSD

### Slow performance

If the app feels slow:

1. **Check database location** - Should be on local SSD
2. **Optimize database** - Rebuild indexes
3. **Clear unnecessary data** - Old logs, orphaned entries
4. **Check database size** - Very large databases may need cleanup

## Technical Details

### SQLite Version

The app uses SQLite 3.x with:
- WAL (Write-Ahead Logging) for reliability
- Foreign keys for data integrity
- Full-text search for OCR content

### Database Schema

Tables are documented in PLAN.md. Key tables:
- `files` - File metadata and hashes
- `drives` - Registered storage locations
- `duplicate_groups` - Detected duplicates
- `faces` - Face detection results
- `persons` - Named individuals
- `scene_analysis` - AI scene/object detection
- `ai_summaries` - Rich natural language descriptions
- `tags` - Searchable tag definitions
- `file_tags` - File-to-tag associations
- `ocr_results` - Extracted text content
- `action_log` - Operation history

Full-text search tables (FTS5):
- `ai_summaries_fts` - Searchable summaries
- `ocr_fts` - Searchable OCR text

### Concurrent Access

The app uses proper locking:
- Single writer at a time
- Multiple readers allowed
- Background operations queue writes

### Transactions

All operations use transactions:
- Batch operations are atomic
- Crashes don't leave partial state
- Can rollback on error
